# Implementation Plan: SML-1702

## Ticket
**enhance-linear-issues: confirm before decomposition even in auto mode**

Auto mode (the default) applies all changes without confirmation, including decomposition — which creates real new sub-issues. That is the one hard-to-reverse action: the Linear MCP server has no delete-issue tool, so undoing means manually canceling orphans, and others may pick them up. Keep auto as the default for title/description/footer/`relatedTo`, but always require explicit confirmation before creating sub-issues (decomposition), even in auto mode. Team reassignment is already recommend-only; no change needed.

## Scope Classification
small — 1 file (`skills/enhance-linear-issues/SKILL.md`).

## Overview
Add a "decomposition gate" to the `enhance-linear-issues` skill: in auto mode, all enhancements except sub-issue creation continue to apply without prompts, but creating sub-issues now always pauses for explicit user confirmation. Three coordinated edits to SKILL.md (Step 1 mode description, Step 8 auto-mode approval flow, Step 9 apply step) keep the behavior internally consistent.

## Approach Decision

Single obvious approach — edit the three referenced sites in SKILL.md so the auto-mode contract carves out decomposition. The skill is a prompt, so the "gate" is expressed as an instruction to STOP and confirm before the sub-issue-creating `Linear:save_issue` calls. No code, no new files.

### Selection Rationale
The ticket names the exact edit sites (Step 1, Step 8, Step 9). Editing those three keeps the change surgical and the cross-references (Step 1 ↔ Step 8 ↔ Step 9) coherent. No alternative structure (e.g., a new top-level "Safety" section) is warranted — it would duplicate guidance already anchored in the approval steps.

### Adaptation Guidance
Non-negotiable constraint: in auto mode, title/description/footer/`relatedTo` must still apply without prompts; ONLY sub-issue creation gains a confirmation gate. If wording gets tangled, prefer adding the gate as an explicit numbered step in Step 8's auto-mode list and referencing it from Steps 1 and 9, rather than rephrasing the whole section.

## Exact Edits (drafted)

### Edit 1 — Step 1, Auto bullet
Append to the existing **Auto** bullet:
> **Exception:** creating sub-issues (decomposition) always requires explicit user confirmation first, even in auto mode — it is the one hard-to-reverse action (the Linear MCP has no delete-issue tool). See Step 8.

### Edit 2 — Step 8, Auto mode list (replace the 4-item list)
```
**Auto mode:**
1. Auto-apply all passing (PASS status) title/description/footer/`relatedTo` changes — but **not** sub-issue creation (see step 4)
2. Skip any flagged proposals — do not apply them
3. Report what was applied and what was skipped (with reasons)
4. **Decomposition gate (always confirm, even in auto):** If any proposal decomposes an issue into sub-issues, STOP before creating them. Present the parent and the proposed child titles/scopes, then require explicit user confirmation. Sub-issue creation is hard to reverse — the Linear MCP has no delete-issue tool, so undoing means manually canceling orphans others may already have picked up. If the user confirms, create the sub-issues (Step 9); if they decline, skip decomposition and report it as deferred. All other changes still apply automatically.
5. No user interaction at any point **except the decomposition gate in step 4**
```

### Edit 3 — Step 9, item 3 (replace)
```
3. If decomposing: **only after the user has explicitly confirmed the decomposition** (the Step 8 decomposition gate — required in both auto and preview modes). Then create sub-issues with `Linear:save_issue` (no `id`, with `parentId`), then update the parent description with `Linear:save_issue` (with `id`). If decomposition was not confirmed, skip sub-issue creation and report it as deferred.
```

## End-to-End Narrative

After implementation, an auto-mode enhancement run works as follows:

1. **User invokes the skill in auto mode** (UNCHANGED) → analysis pipeline runs end-to-end.
2. **Safety review classifies each proposal** (UNCHANGED) → PASS / FLAG.
3. **Apply passing title/description/footer/`relatedTo` changes** (UNCHANGED) → applied without prompts.
4. **A proposal includes decomposition into sub-issues** (MODIFIED) → instead of silently creating sub-issues, the skill STOPS, presents the parent + proposed children, and asks for explicit confirmation.
5. **User confirms** (NEW) → sub-issues are created (Step 9) and the parent description updated. **User declines** (NEW) → decomposition is skipped and reported as deferred; everything else already applied.
6. **Summary reports applied / skipped / deferred** (MODIFIED) → now also surfaces deferred decompositions.

Covers AC1 (steps 3, auto still applies), AC2 (steps 4–5, gate), AC3 (no team-reassignment change).
